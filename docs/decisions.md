# Decision log

Add a new entry whenever a decision changes the product, the architecture, or the plan. Never edit old entries. Add a new one that supersedes them.

| ID | Date | Decision | Reason |
|---|---|---|---|
| D-001 | 2026-11-09 | Build **Ejecto** for the Memecoins and Social tracks. Dropped Segel (DAO-approved release signing). | The Memecoins track had 5 entries and did not grow from Nov 5 to Nov 9. Segel faced npm staged publishing and GitHub immutable releases, its users rarely verify signatures, and its track fit was weak. Ejecto needs no backend, fits the 5-day window, and no refund-on-death memecoin mechanism was found. |
| D-002 | 2026-11-09 | Name: **Ejecto** (from the "ejecto seato" meme). | Chosen by the user. Catchy and uncommon. No crypto project with this name was found. An unrelated token "EJECT" exists. |
| D-003 | 2026-11-09 | Contracts in Rust with `near-sdk` 5.x, built with `cargo-near`. | Most mature NEAR toolchain, good test tooling (`near-workspaces`). |
| D-004 | 2026-11-09 | Linear bonding curve inside the coin contract, no external DEX. | The mechanic needs full control of the reserve and the ability to stop trading at EJECT. |
| D-005 | 2026-11-09 | Two protection layers: pro-rata reserve split at EJECT, plus the Ejecto Fund. | The simulation shows the pro-rata split alone removes all wipeouts (4.4% to 0%, even with the light preset). The fund adds 7% to 19% loss reduction. |
| D-006 | 2026-11-09 | The fund is split by **net basis x time held**, not by tokens or basis alone. | Under the attack test it punishes late whales the most (attacker loses 30.8% to 48.5%). It rewards loyalty and blocks fund farming. |
| D-007 | 2026-11-09 | Alive rule: age at least 14 days, and 14-day buys below max(1 NEAR, 5% of peak 14-day buys). | A fixed threshold treated big and small coins unfairly in the first simulation. The relative threshold made 100% of coins eject within 60 days (median day 28), matching real memecoin lifetimes. |
| D-008 | 2026-11-09 | Fee presets light, standard (default), high. Protocol fee 0.5% of buys. | Lets creators choose the trade-off between protection and trading cost. Standard (2% / 2%) is similar to popular launchpads. |
| D-009 | 2026-11-09 | A full exit forfeits weight. Transfers move basis but not weight. | Prevents buying loyalty from others and rewards staying. Keeps the accounting O(1). |
| D-010 | 2026-11-09 | Coin accounts are keyless with no admin methods. Protocol fees can only go to a fixed account. | Required by the Memecoins track ("No admin key"). Strongest trust signal. |
| D-011 | 2026-11-09 | Demo coins use a short `day_length_sec` (10 to 86399), locked at launch, with a visible DEMO TIME banner. | The full lifecycle (14 days minimum) must fit in a live demo without fake data. |
| D-012 | 2026-11-09 | Static web app: Vite + React + TypeScript on GitHub Pages, RPC reads only. | No backend rule. Simple hosting that judges can open. |
| D-013 | 2026-11-09 | Testnet only for the hackathon. | No audit, no legal review. Also the hackathon allows testnet-only entries for all tracks (rule Q-010). |
| D-014 | 2026-11-09 | SOS rescue is a stretch goal, built only after M4. | Helps the Social track fit, but the core mechanic and a working demo matter more. |
| D-015 | 2026-11-09 | Testnet accounts: master `ejecto.testnet` (created by the NEAR faucet service) with sub-accounts `factory`, `fees`, `ani`, `budi`, `cici`, `whale`. One root `.env` for all config, keys only in the local keychain. | near-faucet.io rejects accounts that do not exist yet. A single funded master keeps funding simple, and sub-accounts keep coin names short (`<symbol>.factory.ejecto.testnet`). |
| D-016 | 2026-11-09 | The factory validates all launch arguments synchronously, with the same rules as the coin's `new`. | Without it, bad input failed inside the async launch batch, and the refund depended on the factory having enough free balance (about 0.9 NEAR free versus a 2.67 NEAR deposit). |
| D-017 | 2026-11-09 | The factory keeps its owner and full-access key during the hackathon. | We may need to fix the factory or upload new coin code. Launched coins stay keyless and cannot be changed either way. The code hash is public in `get_config`. |
| D-018 | 2026-11-09 | Weight is tied to tokens: selling or sending part of a balance sheds the same fraction of weight. Supersedes the transfer part of D-009 ("transfers move basis but not weight" still holds for the receiver, but the sender now sheds). | Review finding: keeping 1 raw token, or moving tokens to a sybil and selling there, kept all old weight and let profit takers dilute loyal holders. The simulation is unchanged because its agents always sell 100%. |
| D-019 | 2026-11-09 | `ft_transfer_call` books accounting in `ft_resolve_transfer`, only for the used part, from the sender's own basis. | Review finding: the old refund path moved basis pro-rata from the receiver's whole holding, so a refunded transfer could drain any registered holder's basis. |
| D-020 | 2026-11-09 | Claims can repeat (reserve part for the current balance, fund part once). | Tokens refunded after a claim were unclaimable. |
| D-021 | 2026-11-09 | The factory sends exactly `launch_deposit` to the coin, refunds the excess at once, and books failed-launch deposits as pull-based refunds. Factory state migrated on testnet with `migrate()`. | Review findings: excess deposit was locked forever in the keyless coin, and the async refund depended on the factory's free balance. |
| D-022 | 2026-11-09 | Web app: Next.js 16 (App Router, static export) + Tailwind CSS 4 + TypeScript, hosted on GitHub Pages. Supersedes the framework part of D-012. | Chosen by the user. `output: 'export'` keeps it a static site with no server, so the no-backend rule holds. Coin pages use a query parameter (`/coin/?id=<account>`) because coins are created at runtime and cannot be pre-rendered. |
| D-023 | 2026-11-10 | Landing design: palette "Cockpit Night" (ink `#0a0a0b`, hazard yellow `#ffd400`, eject red-orange `#ff4d1f`, bone `#ece8df`, HUD green `#3ddc84`), Archivo with the width axis for display type, JetBrains Mono for labels. Section structure inspired by paraape.xyz (big one-word titles, pinned scroll stories, ledger tables), written from scratch. | Chosen by the user. The paraape repo has no license, so no code or assets were copied. |
| D-024 | 2026-11-10 | One 3D pilot (`web/public/mascot/ejecto-pilot.glb`, 2.4 MB, 23k triangles) in a fixed full-screen React Three Fiber layer that follows the scroll: hero, spin, sits on the crash chart, ejects up and left, returns under a parachute built in code, zig-zags beside each section, drifts out of frame before the final call to action. Legs and head move in a vertex shader. | Makes the mechanic a story. The model has no rig, so a shader bends the legs at the knees and turns the helmet. The canvas is click-through; only an invisible box around the pilot is hit-tested for drag-to-spin. |
| D-025 | 2026-11-10 | The landing reads live numbers through public JSON-RPC (`get_config`, `get_coins`, every coin's `status`, and `view_access_key_list` per coin account). Simulation figures come from `web/data/sim-example.json`, exported by `sim/ejecto-sim.mjs`, and are labeled as a model on screen. | No backend and no mock data. Keyless and code-hash claims are shown from chain state, not hard-coded. |
| D-026 | 2026-11-10 | Logo: the pilot helmet mark (off-white shell with an ink outline, red-orange stripe, gold visor), `web/public/brand/ejecto-mark.svg`. Used for the header, footer and favicon. `og.png` (1200x630) and `apple-icon.png` (180x180) were rendered once from it and are served as static files. | Chosen by the user from six concepts. Static PNGs because a static export writes generated metadata images without a file extension, which GitHub Pages would not serve as images. |
| D-027 | 2026-11-10 | Wallet: NEAR Connect (`@hot-labs/near-connect` 0.12), created only in the browser inside a `WalletProvider` for the app pages. Reads stay on our own `fetch` RPC helpers, so `near-api-js` is not needed. Web RPC default: `https://test.rpc.fastnear.com`. | docs.near.org now recommends NEAR Connect over Wallet Selector. It ships its own wallet modal (Meteor, Intear, Ledger, Nightly, EVM wallets, NEAR CLI). `rpc.testnet.near.org` took about 3.4 s per view call in our tests, FastNEAR about 0.2 to 0.6 s. |
| D-028 | 2026-11-10 | App pages: `/coins/` (live list from the factory), `/launch/` (`create_coin` form), `/coin/?id=` (stats, engine meter, bonding curve, buy and sell with contract quotes, your seat, EJECT, claim). The 3D pilot appears in the app only once: a short scene after a successful EJECT. No simulation page. The app footer is folded into a small bar with a button. | Chosen by the user. Keeps the app fast and focused. The simulation page was cut line 2 and the landing already shows the model. "Dying" is a UI hint only (buys under twice the alive line); the contract rule stays `ejectable`. |
| D-029 | 2026-11-10 | Contracts are built reproducibly (`cargo near build reproducible-wasm`, image `sourcescan/cargo-near:0.22.0-rust-1.99.1` pinned by digest in each `Cargo.toml`) and source verified on NearBlocks through SourceScan (`v2-verifier.sourcescan.testnet`). The factory was rebuilt in place: its state was cleared with a temporary cleaner contract, then the reproducible wasm was deployed with `new`. Coins launched after that (starting with `seat`) carry verifiable code; `seato` keeps the old code and is no longer in the registry. | The user asked for verified contracts. NEAR refuses to delete an account with large state, so clearing the state was the only way to reset the registry under the same name. Verification needs a public repo and a clean, pushed commit. |
| D-030 | 2026-11-10 | The coin page has a price history chart (price over time). It is rebuilt in the browser: the public NearBlocks API v3 lists the coin's transactions, the RPC `tx` call (archival RPC as fallback) returns each trade's `ejecto_buy` / `ejecto_sell` event, and replaying the supply through the fixed curve gives the price after every trade. It reloads when the live supply changes. | The user wanted a chart that moves up and down over time. There is no indexer or backend, and public APIs are allowed. The track says the price chart is not scored, so this is for users and the demo only. |

Set `NEXT_PUBLIC_SITE_URL` to the Vercel URL in the project settings; the other `NEXT_PUBLIC_` values have testnet defaults in `web/lib/config.ts`. Supersedes the hosting part of D-022. | Chosen by the user. Still a static site with no server code, so the no-backend rule holds. |
